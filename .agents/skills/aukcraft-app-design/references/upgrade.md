# 升级现有项目

把一套已经在用的桌面 UI 升级到 aukcraft 视觉规范。核心思路：**先审计，后动手，只改视觉层**。用户已经熟悉的布局、组件库、交互流程都是资产，不要为了表达设计而重组它们。

## 升级的取舍原则

- **结构是资产**：布局、组件库、交互流程不动——用户已经熟悉的东西是价值，不是债。
- **变化收敛在上游**：token + 基础组件层承载几乎全部视觉变化；功能组件零改动。
- **优先做减法**：剥阴影、收圆角、降级滥用的 accent——大多数升级是"拿走"而非"添加"。
- **加法只有两个**：焦点/动效纪律（流程 5）与 micro 标签（流程 7）。除此之外不加新元素。

## 流程

### 1. 审计现状

改任何代码之前，先盘点并写下来：

- **现有 token**：CSS 变量、Tailwind 配置、主题入口文件（如 `index.css`、theme provider）
- **圆角用法**：`--radius` 或散落的 `rounded-*` 值
- **阴影用法**：组件库默认带的 `shadow-*`
- **accent 用法**：主题的主色是什么、出现在哪些地方（包括误用：填充、徽标、装饰）
- **已有的好决策**：符合规范的既有模式（见「保留清单」的识别方法）

产出物是一张「现状 → 目标」映射表。写不出这张表就不要进入下一步——完整示例见 `references/peregrine-mapping.md`。

### 2. 生成目标主题

用主题生成脚本从中性色核心 + 产品 accent 生成目标变量，避免手算 HSL 出错：

```bash
python scripts/generate_theme.py --accent "<产品accent>" --format shadcn   # 或 css / tailwind
```

注意脚本的对比度警告：暗色界面用 accent 的 400 阶，不足 4.5:1 时换更亮的阶。脚本另带**槽位塌缩门禁**：hover 级表面与 card 明度差 <3% 时拒绝生成——三级表面（base < raised < hover）是硬约束，塌缩成两级会让悬停反馈全部死亡。

### 2.5 槽位消费审计（不可跳过）

token 重映射**之前**，先盘点每个语义槽的所有消费者，逐个决定处置——否则 token 级改动会从组件"后门"误伤。强制产出一张消费场景矩阵：

1. grep 所有消费 `--primary` / `--accent` / `--muted` / `--secondary` 的组件与 class（shadcn 项目重点查 `components/ui/*`）
2. 逐行标注性质：主操作填充 / 静态填充 / 选中标记 / 悬停底色 / 实时状态
3. 按 accent 配给纪律决定每行的新值（参考 `peregrine-mapping.md` 的矩阵实例：slider/switch 改中性、checkbox/radio 未选描边改 `border-input`）
4. 特别警惕的"后门"消费者：`slider` 的 Range/Thumb、`switch` 的 checked 态、`checkbox`/`radio` 的未选描边——它们都消费 `--primary`，只换 token 会把它们全部染色

写不出这张矩阵就不要进入下一步。完整实例见 `references/peregrine-mapping.md` 的「accent 消费场景矩阵」。

### 3. 重映射变量（大部分视觉变化发生在这一步）

把生成的变量块替换进主题入口。改动限定在**上游**：CSS 变量 + 基础组件层（如 shadcn 项目的 `components/ui/*`）。功能组件（设置项、业务面板）应当**零改动**——如果你发现自己在改功能组件修颜色，说明上游某个 token 定错了，回去改上游。

### 4. 圆角 + 阴影一轮

- `--radius` 收到 4px（md 3px、sm 2px）
- 从基础组件层剥掉所有 `shadow-*`；层次由发丝线承担
- 检查弹层/下拉在零阴影后是否仍可从背景中读出——靠 `raised` + 发丝线 + 遮罩，不是靠把阴影加回来

### 5. 焦点 / 动效一轮

- 焦点环改为 1px accent 描边、2–3px 偏移（替代组件库默认的粗 ring + offset）；**≤20px 的小控件（checkbox/switch/radio/slider thumb）用 2px**——3px 偏移对小控件比例失调
- 过渡时长缓动统一到 `ease-lock`
- 补上 `prefers-reduced-motion` 降级：直接变色、禁用缩放

### 6. accent 纪律一轮

全局搜索 accent 色的每一处使用。凡不属于「焦点 / 唯一主操作 / 链接 / 选中标记 / 实时状态」的，一律降级为 `ink` 或 `muted`。白色或亮灰的主按钮（shadcn 暗色默认 `--primary: 0 0% 98%`）是最常见的品牌断裂点，优先处理。

### 7. Micro 标签一轮

分组标题与状态文字改为 mono micro 标签（JetBrains Mono、全大写、`0.15em` 字距、`muted` 色）。这通常是升级中唯一新增的字体元素。

### 8. 在真实窗口尺寸下验证

不是最大化的浏览器，而是 app 实际运行的窗口尺寸（如 Peregrine 的 960×560）。过一遍下方检查清单。**除静态检查外必须做动态三态验证**：在真实窗口里逐一触发 hover / 键盘焦点 / 选中态，确认每处都有可见反馈——静态 token 检查查不出"悬停死在浮层上"这类事故。

## 保留清单：识别"本来就对"的决策

升级不是翻新。发现以下模式时，识别它们、保留它们，最多只做 token 级对齐（如换颜色值），不要替换实现：

- **自定义滚动条**（自动隐藏、细轨道）——保留；颜色对齐到 `muted` 梯度
- **紧凑的信息密度**——app 的 `p-6` / `space-y-6` 级间距是对的；不要膨胀成网站级留白
- **固定暗色主题**——对工具类 app 是正确的；不要顺手加亮色模式
- **运行时 i18n**——app 的正确模式（区别于网站的双语路由）；关键技术术语（crate、CI、PR、TDD）在所有语言中保持英文
- **平台原生组件**——托盘、OS 菜单、原生对话框；它们属于 OS，不属于品牌改造范围

## 升级情形检查清单

在 SKILL.md 共用清单之外，升级情形额外确认：

- [ ] 布局、tab、流程、组件库未动——diff 只含 token/class 级改动
- [ ] 改动集中在上游（主题入口 + 基础组件层），功能组件零改动
- [ ] 「现状 → 目标」映射表与「accent 消费场景矩阵」中的每一项都已落地，无遗漏无计划外改动
- [ ] 三级表面成立：base < raised < hover 两两可辨，`--muted`/`--secondary`/`--accent` 未塌缩到 raised
- [ ] 动态三态验证通过：hover / 焦点 / 选中在真实窗口逐一触发，反馈均可见
- [ ] 已有的好决策（滚动条、密度、纯暗色、运行时 i18n、原生组件）被保留
- [ ] 在 app 真实窗口尺寸下验证通过
